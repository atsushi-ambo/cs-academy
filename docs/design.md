# cs-academy 設計案（構想段階）

2026-11-26作成。実装はまだしない。本書は構想と設計のみ。
レビュー（Claude Sonnet、Codex制限中のため代替）の指摘を反映済み。

## 1. ゴールと完了の定義

**ゴール**: 文系出身の本人が、英語で学びながら、要件定義からアーキテクチャ、実装、運用、AI活用までを自分で判断し、その理由を英語で説明できるシニアエンジニアになるための、本人専用の学習アプリ。このMacのローカルだけで動く。

**最終の完了条件**（数年単位。挫折しないよう中間目標を別に置く）:

1. 最終課題（Capstone）として、AIを使ったWebサービスを要件定義→設計→実装→k8sで運用→障害対応まで1人で行い、英語の設計書とADR（設計判断の記録）がGitに残っている。
2. スキルマップの「Core」スキルすべてに到達の証拠（テストが通るコード、提出物のコミット、英語の説明）が紐づいている。
3. 英語で設計のトレードオフを5分で説明できる（週1回の英語での口頭練習の記録が残っている）。

**中間目標（半年ごと）**: 各Stageの修了課題（Gate）に合格する。

**アプリ初版（MVP）の完了**: サンプルUnit（Lists）を画面だけで最後まで遊べる（読む→四択→コードを書いてテスト→Boss）。四択が復習に出て、進捗がSQLiteに残り、バックアップから復元できる。

## 2. 前提と現実的な期間

- 利用者は本人1人。`127.0.0.1` で待ち受ける。
- 想定: 平日30分×5 + 週末2時間 ≒ **週5時間（年間約250時間）**。
- 全部を深くやると5〜8年かかる。そこで各Stageを **Core（必修）** と **Deep（任意の深掘り）** に分ける。Coreだけなら約4年（`content/curriculum.yaml` の時間予算の合計 1,115時間。演習だけでなく、ハンズオン・復習・読書・Boss・Gateを含む。週5時間なら約4.3年、週7時間なら約3.1年。実力診断で既習のStage 1前半を飛ばせば、その分短くなる）。
- 2027年5月の出産前後は「15分モード」（復習と英語だけ）に切り替えられる。中断しても復習の山で潰れないよう、復習数に上限を設ける。
- 教材は英語が主。ただし最初（Stage 0〜1）は、概念と英語を同時に学ぶ負荷を下げるため、日本語の補足（単語の意味、短い要約）をタップで出せる。Stageが進むごとに日本語補足を減らす。
- 本は各Moduleで「必読1冊＋参照」に絞る。手元の本を全部読む前提にしない。

## 4. 進め方の順序（アプリ開発が学習を食わないように）

アプリを作ること自体に時間を取られると学ぶ時間がなくなる。そこで:

1. **Phase 0（アプリなしで今すぐ）**: 本書のStage 0〜1をMarkdownのチェックリストにして、既存のツール（Shiori、kumite、Ankiなど）で1〜2か月回す。何が本当に必要かを確かめる。
2. **MVP**: 必要と分かった機能だけを小さく作る（下の P0）。
3. 以後、学習が進んで必要になった機能を足す。アプリの開発そのものを、Stage 3（Web・DB）とStage 7（AI）の演習課題として扱う。

## 5. 学び方: 読むだけにしない（手を動かす・ゲーム性）

2026-11-26の追加依頼: ハンズオンで実際にコードを書く、四択で復習する、ゲーム性があり手を動かす。テキストを読むだけにしない。

### 5.1 Unitは「ステップの連続」

1つのUnitは、長い文章ではなく **3〜10分の短いステップを20〜30個** つないだもの。読むステップは連続2つまでとし、必ず手を動かすステップを挟む。

| ステップの種類 | やること | 判定 |
|---|---|---|
| Read | 短い解説（画面1枚、3分以内）。図と例つき | 読んだら次へ |
| Predict（四択） | コードを見て「出力はどれ？」を先に予想する。外れた選択肢にも解説 | 自動 |
| Try it | 画面のエディタでコードを書き換えて実行し、結果を見る | 実行できたら次へ |
| Code（課題） | 問題文・**制約・入出力例**を読み、関数を書く。「Run」（自分の入力で試す）と「Run tests」（判定）を分ける。落ちたテストと理由を表示。ヒントは3段階（方針 → 手順 → ほぼ答え）。使うとXPは減るが★1は取れる。模範解答と解説は合格後か3回失敗後に開く | テスト |
| Fix the bug | 壊れたコードを渡され、テストが通るように直す | テスト |
| Parsons | バラバラのコード行を正しい順に並べる（初心者向け） | 自動 |
| Terminal | 自分のターミナルで行う作業（Git、Docker、kubectl）。結果を貼る、または判定スクリプトで確認 | スクリプト |
| Explain | 学んだことを英語で2〜4文書く。ルーブリックで自己採点、任意でAI添削 | 自己採点 |
| Boss | Moduleの最後の総合課題。四択＋コード＋バグ修正を時間内に。合格でModuleクリア | 自動＋テスト |

各Moduleの最初のステップは「全体像」にする（身近な例 → このModuleで学ぶことの一覧）。Unitは順に解放するが、実力診断（5.5）で「スキップ」を選んだUnitは開いた状態にする。

### 5.2 四択の復習（Review Arena）

- 各Unitの四択・コード穴埋め・英単語が自動で復習カードになり、FSRSで出題日が決まる。
- 1回5分・10問のラウンド形式。連続正解でコンボ、間違えた問題はその場で解説を読み、ラウンドの最後にもう一度出る。
- 復習は「今日の分」に上限を設け、休んでも山にならない（15分モードと共通）。

### 5.3 ゲームの要素

P0で作るのはXP・Daily quest・ストリークまで。スキルの星・地図と宝箱・バッジ・学習カレンダーはP1、模擬面接はP5。

| 要素 | 内容 | 注意 |
|---|---|---|
| XP・ランク | ステップ・テスト合格・復習でXP。ランク Intern → Junior → Mid → Senior → Staff は、XPではなく **Stageの合格（Boss）** で上がる | 遊んだ量ではなく実力で上がるようにする |
| スキルの星 | スキルごとに★0〜3。★1＝解けた、★2＝復習でも正解、★3＝ハンズオンの証拠あり。**「次の★まであと何をするか」を常に表示** | Path mapに表示 |
| Daily quest | 「復習10問」「コード課題1つ」「英語の説明1つ」など、その日の時間に合わせて3つ | 15分モードでは1つ |
| ストリーク | 連続学習日数。週2日まで休んでも途切れない | 出産前後を考えて、罰を与えない設計 |
| Boss | Moduleの総合課題。不合格でも、弱いスキルを示して再挑戦できる | — |
| 地図と宝箱 | Path mapは地域を順に解放する地図。Boss合格で次の地域が開く。脇道の宝箱は任意の発展課題（Deep） | LeetCode Questを参考 |
| 完走バッジ | Moduleの完走でバッジ。外部（LeetCode 75など）を解いたことは本人の任意の手動記録で、アプリ内の完走条件には使わない | 他人とのランキングは作らない |
| 学習カレンダー | 週の学習日数と月のヒートマップ | 休んでも責めない表示にする |
| 模擬面接 | Stage 7で、アプリ内のタイマーとルーブリックの自己評価で行う模擬面接（コーディング60分、システム設計60分、英語の行動面接30分）。任意でAIの講評（参考値）と外部サービスへのリンク | HackerRankのAI模擬面接を参考 |
| Bug hunt | 実務にありがちなバグ（オフバイワン、エイリアス、N+1、競合）を探すタイムアタック | Stage 2以降 |
| Incident drill | Stage 6〜7で、kindのクラスタやWebアプリに障害を仕込み、ログから原因を探して直す | 判定スクリプトで確認 |

既存の `learnpython/fde_game.py`（キャンペーン、ブリッツ、コンボ、ボス、ランク）の遊び方を参考にする。

### 5.5 実力診断（既習の範囲を飛ばす）

本人はすでに Recursion の CS初級を修了し、中級(旧)を76%まで進めている。HackerRank の Python は 215/220点（2026-11-27 時点、[reference-platforms.md](reference-platforms.md)）。分かっている内容を最初から読ませない。ただし、診断で確かめていないスキルまで「済み」にはしない。

- 単位は **Unit**。各Unitの確認テストは、そのUnitの四択から数問＋コード課題1つ（5〜10分）。外部サービスの進捗は「どこから診断を勧めるか」の材料にだけ使う。
- 合格したUnitは「スキップ候補」になり、**本人が選んで**スキップする。Terminal・ハンズオンが要るUnit（Gitや環境構築など）は、短い診断では確かめられないので候補にしない。
- スキップしたUnitの四択は、1日数枚ずつ復習に足す（既存のカードと重複させない）。FSRSは実際の復習の回答で更新する。間違えたら、そのUnitをTodayで勧め直す。解放と進捗はそのまま。
- 診断の合格で★・Boss・Gate・ランク・バッジは付かない。これらはそれぞれ所定の課題で取る。
- 受け直しても復習の履歴は引き継ぐ。ヒントの3段階目や模範解答を見たコード課題は、診断に使わない。
- P0では Lists の1 Unitだけで作り、Stage 0〜1 全体へ広げるのはP1。

## 6. 構成

```text
cs-academy/
├── app/            Python（標準ライブラリ中心）のローカルWebサーバー
├── web/            素のHTML/CSS/JS（フレームワークなし）
├── content/        カリキュラム定義（YAML、英語。自作のものだけをGit管理）
├── runner/         演習の実行（P0からPython、隔離コンテナ）
├── labs/           k8s・ネットワークのラボ定義と判定スクリプト（P4）
├── data/           私有データ（DB、録音、教材から作った問題案。Git対象外、権限0700）
└── docs/
```

| 部分 | 選択 | 理由 |
|---|---|---|
| サーバー | Python 3.13（標準ライブラリ中心。必要なら小さなWebフレームワークを1つだけ、理由を書いてから） | 本人が学ぶ言語で作り、アプリのコードも教材として読めるようにする |
| DB | **SQLite**（単一ファイル） | 本人1人・ローカル。Docker常駐や起動忘れがなく、バックアップも簡単 |
| 画面 | 素のHTML/CSS/JS | 依存を増やさない方針。フォームと一覧が中心 |
| FSRS | 公開されているFSRSのアルゴリズムを実装、またはPythonの公式実装を1つだけ使う | 復習間隔の計算は実績のある方式を使う |
| kumiteとの関係 | kumiteのコードは**切り出さない**。Stage 7でkumiteへリンクし、必要なら進捗をkumiteのAPIから読むだけ | kumite側の大改修を避ける |
| AI | 交換可能な接続部分。既定はローカルのOllama、必要なときだけ本人がボタンでClaude API | 自動で外部に送らない。APIキーはキーチェーン/環境変数で持ち、画面へ渡さない |

ポート: `PORTS.md` の次の空き区画 **4350–4359**（画面兼API 4350、e2e 4356）。実装時に `PORTS.md` へ追記することを完了条件に含める。

### ローカルAPIの守り

`127.0.0.1` だけで待ち受けても、ブラウザ経由の攻撃（CSRF、DNSリバインディング）は防げない。kumiteと同様に、Host・Origin・独自ヘッダーを検証し、状態を変える操作はPOSTだけにする。サーバー上の任意パス・任意URLを画面から指定できるAPIは作らない。

## 7. 演習の実行（P0からPython。C・SQL・k8sは後の段階）

自分のコードやAIが作った課題が、Macを壊したり情報を外に出したりしないようにする。

- 実行は毎回使い捨てのDockerコンテナ。`--network none`、非rootユーザー、`--cap-drop ALL`、`--security-opt no-new-privileges`、`--pids-limit`、読み取り専用ルート＋tmpfs、CPU・メモリ・時間（10秒）・出力サイズの上限。ホストのフォルダはマウントしない。コードは標準入力か一時コピーで渡す。
- Dockerを呼ぶのは専用のrunnerプロセスだけ。受け付ける入力は「課題ID＋ソースコード＋（Runのときだけ）サイズ上限つきの標準入力データ」に固定する。Run testsでは、サーバーが課題IDからテストを選んで渡す（画面からテストは渡せない）。合否・XP・解答を開くための失敗回数はRun testsの結果だけで数え、runnerの起動失敗は数えない。Dockerソケットはどのコンテナにも渡さない。
- C言語はrunnerの外では実行しない。
- ネットワークの演習（netns）はmacOSにないので、OrbStackのLinux VM内で行う。
- k8sラボは専用のkubeconfigと `--context kind-cs-academy-<ラボ名>` を必ず明示し、それ以外のコンテキストなら中断する。ラボが作ったクラスタだけを削除する。
- 判定: Python/C はテストまたは期待出力、SQLはテストごとに作って消す一時DB、k8sは判定スクリプト。設計・英語の説明はルーブリック（観点ごと0〜3点）の自己採点。AIの採点は参考値で、Gateの合否には使わない。

## 8. データモデル（主なもの）

- `stages` / `modules` / `units`: カリキュラム（content/から読み込み、版を持つ）
- `skills`: スキル（Core/Deep）。unitと多対多
- `sources` / `source_refs`: 参照元（本・コース・Web・問題サイト）とライセンス、unitからの参照（章・ページ・URL）
- `activities` / `attempts`: 問題・演習と回答・提出結果
- `review_cards` / `review_logs`: FSRS
- `evidence`: スキルの到達の証拠（提出物のGitコミット、テスト結果、説明文）
- `vocab`: 英単語

本の本文はDBに保存しない（参照の章・ページだけ）。

| Shioriの技術書PDF（約30冊） | 章・ページを読む範囲として示す。問題を本から作りたいときはkumiteの教材ノート（出典付き・本人承認）を使う | 本文の保存・長い引用・Git管理 |
| Kindle | 書名・章を読む課題として割り当てる | 自動取得、DRM回避、画面の自動キャプチャ |
| Recursion | 本人が受講中のコース名とリンクを対応表にする。進捗は本人が記録。本人がログインした画面で構成を見るのはよい（2026-11-27 に実施） | Claudeがパスワードを入れてログインすること、スクレイピング、内容の転記 |
| LeetCode / HackerRank | 問題IDとURLでリンクし、自分の解答はローカルに保存 | 問題文のコピーや要約・言い換え |
| CS50（CC BY-NC-SA 4.0）、MIT OCW（CC BY-NC-SA）、OSSU、teachyourselfcs | シラバスとの対応、講義へのリンク。これらを元にした確認問題は派生物として扱い、個人の非商用利用に限る | 公開・再配布 |
| 公式ドキュメント（Python、Kubernetes、PostgreSQL、OWASP など） | 一次情報として最優先 | — |

食い違ったときの優先順位: **公式ドキュメント > 原著（英語） > 大学のコース > 日本語書籍 > AIの生成文**。AIが作った問題・解説は、参照元と照合して本人が承認するまで「draft」として出題しない。

## 10. バックアップ

学習履歴・復習予定・録音は数年分の資産になる。

- `make backup`: SQLiteのオンラインバックアップ＋ `data/` をまとめて、日付つきでGit対象外のバックアップ先へ保存。Time Machineとは別に保管する。
- 復元手順を書き、復元テスト（バックアップから立ち上げて件数を比べる）を自動テストに含める。
- DBの変更はマイグレーションで行い、データを消す自動初期化はしない。

## 12. 教材の品質基準と作り方

2026-11-26の追加依頼: 題名だけでなく、中身の解説・ハンズオンまであり、これだけで学べる「教材として提供できるレベル」にする。

### 1 Unitの構成（サンプル: `content/stage-1-python/m03-collections/u01-lists/`）

| ファイル | 中身 |
|---|---|
| `unit.yaml` | 学習目標、前提Unit、所要時間、スキル、参照先（公式ドキュメント・コース・練習問題のURL）、英単語と日本語の意味 |
| `steps.yaml` | **アプリで遊ぶ本体**。Read・Predict（四択）・Try it・Parsons・Fix・Code・Terminal・Explain・Bossのステップを順に並べる（5.1節） |
| `lesson.md` | 1ページで見直すための要約シート（読むモード）。なぜ必要か → 図 → 例 → よくある間違い → 実務での使われ方 → まとめ |
| `handson.md` | ターミナルで手を動かす手順。期待する出力、わざと壊して観察する手順、Gitへのコミット（＝証拠）、完了チェックリスト |
| `exercises/` + `tests/` | 書きかけのコードと自動テスト（標準ライブラリのunittest）。境界値・空の入力・入力を壊さないことまでテストする |
| `solutions/` | 模範解答と解説（なぜそう書くか、計算量、次に学ぶこと、外部の練習問題） |
| （四択） | `steps.yaml` の Predict。**すべての選択肢に「なぜ違うか／なぜ正しいか」**を付ける。Unitの四択は復習カードになる |

### 品質基準（全部満たしたものだけ `status: published` にする）

1. **自己完結**: 外部リンクを開かなくても、Unitの目標を達成できる。
2. **正確**: 技術的な記述を公式ドキュメントと照合している。コードはすべて実行して確認している。
3. **演習は自動で検証済み**: 模範解答でテストがすべて通り、書きかけのコードではすべて落ちる（CIで毎回確認）。ハンズオンの「期待する出力」は実際に実行した結果と一致している。
4. **初心者向けの英語**: Stage 0〜2は短い文と基本語彙（目安CEFR B1）。新しい用語は初出で定義し、`vocab` に日本語の意味を入れる。Stageが進むほど実務の英語に近づける。
5. **つまずきを先回り**: よくある間違いを少なくとも1つ、理由つきで示す。
6. **実務につながる**: 本人の仕事（インフラ、サーバー、ログ）に近い例を使う。
7. **オリジナル**: 外部の教材（Recursion、LeetCode、HackerRank、CS50、本）の文章・問題・図をコピーしない。構成や扱うテーマを参考にするのはよい。
8. **手を動かす**: Readは連続2つまで。1 Unitに Predict 5問以上、コードを書く課題（Code/Fix）3つ以上、ハンズオン1つ、Boss 1つ。
9. **未習事項を使わない**: 演習・四択で使う構文や関数は、そのUnitか前提Unitで説明済みのものだけ。
10. **四択の質**: 全選択肢に解説、正解の位置を偏らせない、紛らわしい言い回しを避ける。答えはコードを実行して機械的に確かめる。
11. **アクセシビリティ**: ASCIIの図には文章による説明を付ける。色だけで正誤を示さない。文字サイズを変えられる。

### 機械検証の範囲

- 演習: 模範解答で全テスト合格、書きかけで全テスト失敗（`NotImplementedError` によるエラーも「失敗」として数える）。
- Predict: `code` を実行した出力と、正解の選択肢が一致する。
- Parsons・Fix・Boss: 正しい答えで合格、出題したままのコードで不合格。
- lesson・handson のコード: 実行できるものは全部実行し、書いてある出力と比べる。
- 対象のPython: 3.9（macOS標準）と 3.13 の両方。
- 英語: 1文の長さ（目安20語以下）と、`vocab` にない難しい語の一覧を出す。
- サンプルUnitでは、ここまでを手元のスクリプトで確認済み（2026-11-26）。

### 版と、直したときの扱い

- `unit.yaml` の `version` を上げ、`status` は draft → published。公開後の修正は版を上げ、学習履歴は旧版のまま残す。
- 四択の答えが変わる修正をしたら、その復習カードの記録を初期化する。表現だけの修正なら記録を残す。
- スキルIDを変えるときは、旧IDから新IDへの対応を書いたマイグレーションを用意する。
- レビューの指摘と本人の「分からなかった」印は、`data/feedback/`（Git対象外）にUnit ID・ステップID・内容・重要度で記録し、直したら版と一緒に閉じる。
- 教材のライセンス: 自作の教材は本人の私的利用。外部の教材は含めない。

### 作り方（量産の流れ）

全体で213 Unit（`content/curriculum.yaml`、8 Stage・46 Module）。Recursion のロードマップの全トピックとの対応は [recursion-roadmap-coverage.md](recursion-roadmap-coverage.md)。1 Unitは20〜30ステップ・60〜120分。学習の進度より1 Stage先まで用意しておけばよく、全部を先に作らない。

1. **Module計画**: 学習目標とUnitの並びを決める。参考にするのは CS50 / MIT / OSSU のシラバス、Recursion・LeetCode Exploreの構成、手元の本の目次。
2. **下書き**: AI（Codex、Claude）がUnitの全ファイルを書く。本から作るときは、kumiteの教材ノートで本人が選んだページを根拠に使い、本文はコピーしない。
3. **機械検証（スクリプト）**: YAMLの形式、リンク切れ、コードの実行、テスト（解答は合格・未着手は不合格）、ハンズオンの期待する出力との一致、英語の難易度（文の長さ・未定義の語）。
4. **AIレビュー**: 別のモデルが正確さと分かりやすさを品質基準に沿って確認する。
5. **本人が学習して承認**: 実際に解いて、分からなかった箇所に印を付ける。印の付いた箇所は手順2へ戻す。承認したら `published` にする。

### 外部サービスの使い方

| サービス | 使い方 |
|---|---|
| Recursion（無料の初級＋本人のアカウント） | コースの構成（二進数・浮動小数点・論理演算から、OS・ネットワーク・DB・設計へ進む順序）をModule計画の参考にする。本人の受講とアプリのUnitを対応づけ、「Recursionのこのレッスンの後にこのハンズオン」と案内する |
| LeetCode（Explore、Study Plan の LeetCode 75・SQL 50、Quest） | 各Unitの「次の練習」として、問題番号とURLを示す。Stage 2のパターン別Module（s2.m08）はLeetCode 75の見出しに対応づける。解き終えたら英語で一言書く |
| HackerRank（Python、SQL、C、Algorithms、AIの模擬面接） | Stage 1〜3の追加練習。システム設計・AIの模擬面接はStage 7の仕上げに使う |
