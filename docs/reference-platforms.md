## 観察した仕組みと採否

### LeetCode

| 仕組み | 観察 | 採否 |
|---|---|---|
| Quest | 分野ごとの地図。地域（例: 線形 → 系列 → 連想 → 整列 → 再帰 → グラフ → 木 → 戦略）を順に解放。分岐の脇に宝箱 | **採る**。Path map を「地図＋順に解放」にする。Boss 合格で次の地域が開く。宝箱＝任意の発展課題 |
| Study Plan | 問題を**パターン別の見出し**（Two Pointers、Sliding Window、Prefix Sum、Monotonic Stack…）で並べ、期間の目安（1〜3か月）と完走バッジ | **採る**。Stage 2 のアルゴリズムはパターン単位の Unit にし、各 Unit の「次の練習」に LeetCode 75 の該当問題を割り当てる |
| 週間ランキング | 他人と比べる | 採らない（1人用。比べるなら過去の自分） |

### HackerRank

| 仕組み | 観察 | 採否 |
|---|---|---|
| スキル別の点数と星 | 分野ごとに点数を積み、「あと5点で次の星」と表示 | **採る**。スキルの★に「次の★まであと何をすればよいか」を出す |
| サブドメイン | Python を Introduction / Strings / Sets / Collections / Errors / Classes / Functionals / Regex / Closures and Decorators… に分割 | 参考。Stage 1 の Module 分けと照合し、抜け（Regex、Closures and Decorators）は curriculum.yaml で確認 |
| 問題の型 | 問題文 → 入力形式 → 制約 → 入出力例 → エディタ | **採る**。Code ステップに「制約」と「入出力例」の欄を必ず置く |
| AI模擬面接 | Technical Screen 30分、Coding 60分、System Design 60分、Behavioral 30分 | **採る（Stage 7）**。時間制限つきの模擬面接モード。AI の採点は参考値（design.md 7章） |

### Recursion（無料の初級）

| 仕組み | 観察 | 採否 |
|---|---|---|
| 章の最初の全体像ページ | 章で学ぶことの地図、身近な例から入り、最後に「このセクションで学ぶこと」の一覧 | **採る**。各 Module の最初の Unit の最初のステップを「全体像」にする |
| 順に解放 | ページは前を読むまで鍵。2〜3ページごとにクイズ | 採る（すでに steps.yaml の並びがこの形）。ただし実力診断に合格した範囲は鍵を外す |
| 実生活の文脈の問題 | 料金と需要のような身近な題材、グラフ付き | 採る（品質基準6と同じ方向） |
| 段階的なヒント | 1つの問題にヒント3段階、別タブで解説と解答、他人の解答 | **採る**。Code/Fix ステップにヒントを3段階（方針 → 手順 → ほぼ答え）。ヒントを使うと XP は減るが★1は取れる。解答は合格後か3回失敗後に開く |
| 自分の入力で試す / テスト / 提出 | 「カスタム入力」で実行、テストで確認、提出で判定を分ける | **採る**。Run（自分の入力）と Run tests を分ける（5.4 の Code editor） |
| 学習カレンダー | 週の学習日数と月のヒートマップ | 採る（Today 画面）。ストリークと同じく罰は与えない |
| ダッシュボード | 「前回の続き」に何%・何ページ目かを出し、ボタン1つで再開 | 採る（Today 画面） |
| 複数言語の切り替え | 同じ問題を Python / JS / C++ / Java / PHP で | 採らない（Python 中心、C は必要な所だけ） |
| チーム開発・AIコードレビュー | 有料 | チーム開発は対象外。コードレビューは Ollama/Claude のボタン（design.md 6章） |
